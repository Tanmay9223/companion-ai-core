# Evaluation

*Note: Evaluation is an optional stretch goal. Do not prioritize this over a working core memory loop.*

This document designs a lightweight evaluation harness for the Companion-AI. The philosophy is to prioritize deterministic assertions on the state of the memory database before relying on subjective LLM-as-judge evaluations.

## Approach
1. **Structured Assertions**: Run synthetic conversation scripts and assert that specific SQLite rows exist with the correct status (`active` vs `superseded`).
2. **State Inspection**: Assert that retrieval returns the correct ID for a given context.
3. **LLM Judge**: Use a powerful model (e.g., GPT-4) only for subjective qualities like tone drift.

## Suggested Metrics

### Recall Accuracy
- **What is measured**: The system's ability to fetch the correct active memory when requested.
- **Calculation**: `correct expected recalls / total recall test cases`
- **Pass/Fail**: Pass if the LLM response semantically includes the targeted memory fact.

### Contradiction Resolution Rate
- **What is measured**: The system's ability to supersede old facts with new contradictory facts.
- **Calculation**: `correctly superseded contradictions / total contradiction cases`
- **Pass/Fail**: Pass if the database state shows the old fact as `superseded` and the new fact as `active`.

### Stale-Memory Error Rate
- **What is measured**: How often the system retrieves and presents a `superseded` fact as current truth.
- **Calculation**: `stale facts presented / total recall cases`
- **Pass/Fail**: Pass if 0. Stale facts should only be presented if the user asks for historical context.

### Relevant-Memory Precision
- **What is measured**: Whether the injected context contains *only* relevant facts.
- **Calculation**: `relevant memories in prompt / total memories in prompt`
- **Pass/Fail**: Pass if irrelevant memories are successfully filtered out of the prompt.

### Persona Fact Consistency
- **What is measured**: Adherence to the stable opinions defined in `config/persona.yaml`.
- **Calculation**: `consistent persona responses / total persona questions`
- **Pass/Fail**: Pass if the model's answer semantically aligns with the YAML config.

### Persona Tone Consistency
- **What is measured**: Adherence to the conversational style guidelines.
- **Calculation**: LLM-as-judge score (1-5) on "Warmth and Peer-like Nature".
- **Pass/Fail**: Pass if average score > 4.0.

## Limitations of LLM-as-Judge
If an LLM judge is utilized, the following limitations must be acknowledged:
- **Judge Inconsistency**: The same model may rate the same response differently on subsequent runs.
- **Prompt Sensitivity**: Slight changes to the rubric prompt can drastically alter scores.
- **Provider/Model Bias**: Models tend to prefer responses generated by their own family of models.
- **Cost**: Running an evaluation suite over hundreds of turns is expensive.
- **Non-Determinism**: It is difficult to run CI gating on subjective, non-deterministic tests.

## Oracle Baseline (Optional)
To contextualize the prototype's performance, an oracle baseline can be defined:
- **Definition**: A stronger model (e.g., GPT-4) is given the *entire* ground-truth memory context directly in the prompt, bypassing the retrieval layer.
- **Usage**: The oracle produces an ideal expected response for a user query. The prototype's response (using its own retrieval logic) is then compared against the oracle's response to measure degradation caused by the retrieval bottleneck.

*Do not pretend this harness produces scientifically rigorous companion-quality measurement. It is intended for rapid, directional engineering feedback.*
